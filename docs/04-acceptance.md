# 04 · 验收标准（AC-01 ~ AC-46）

> 验证方法：`P` = Playwright/人工点检；`S` = 服务端 API 断言（curl 可复现）；
> `C` = 代码/静态检查。全部标准可在当前实现中逐条核对。

## 点亮进度

- **AC-01（P）** 主页顶部毛玻璃卡显示「已点亮 N / 333 个地级市」，N 与实际 `unitId` 去重数一致；
  副行显示含直辖市/特别行政区口径与照片数、省级行政区数。
- **AC-02（P）** 创建一次新城市的旅行后不刷新页面，地图上该城市立即出现琥珀照片气泡，进度 +1。
- **AC-03（P）** 同一城市创建第 2 次旅行：进度不变（去重），气泡略增大，悬停卡出现「2 次旅行」；
  点击（桌面）进入城市页可见两次旅行按年分组。
- **AC-04（P）** 筛选「已点亮/未点亮」：未点亮模式显示灰度小点（与家庭气泡形状明显不同），
  已点亮模式隐藏未点亮标记；成员/年份筛选后地图与进度副行联动。

## RBAC 与隐私

- **AC-05（P）** 以 VIEWER（演示角色「爷爷」）进入：无「创建新旅行」「上传照片」「写下感想」「选片」「打卡」入口或按钮均禁用并说明原因；点检不存在可绕过的隐藏可点元素。
- **AC-06（P）** MEMBER B 无法在 UI 中删除 MEMBER A 创建的旅行（入口不出现）；OWNER 可见「清理他人内容」入口。
- **AC-07（S）** 伪造 `X-Member-Id` 为 VIEWER 成员，`POST /sync/push {type:'trip.create'}` → 返回 403。
- **AC-08（P）** 家庭空间页显示「仅家庭可见」，整个 App 无任何公开分享/公开主页/游客链接入口；
  `setFamilyVisibility` 的取值白名单仅 `family|private`（**C**：`store.js` 无 public 分支）。
- **AC-09（P）** 非身份成员在 UI 中无法看到邀请码（显示「仅创建者可见」）；重新生成邀请码后旧码在服务端 join 校验中失效（**S**）。

## 每人最多 3 张 · 服务端校验 · 个人独立选片

- **AC-10（P）** 每位成员「我的最佳照片」最多 3 张：快选第 4 张被拒并 Toast 说明。
- **AC-11（S）** 直接向服务端推送 4 张精选（绕过前端）：`POST /sync/push {type:'best.set', photoIds:[4个]}` → **422**，错误信息含「每人每趟最多 3 张」。
- **AC-12（S）** `best.set` 的 `payload.memberId ≠ X-Member-Id`（A 代 B 选片）→ 422「选片权归个人」。
- **AC-13（P）** 成员 A 的精选变更不影响成员 B 的精选；「家庭精选聚合」区展示所有成员各自的选择，不出现「全家票选/统一结果」字样或功能。
- **AC-14（P）** 照片 ≥4 张时详情页出现「对比 PK 帮我选」，PK 结果仅为建议，必须经本人点「用这 3 张」确认。
- **AC-15（P）** 精选可排序（↑/↓ 写入 order 1..3）、可替换、可移除；移除后槽位显示「第 N 张」。

## 感想独立归属

- **AC-16（P）** 详情页每位成员感想独立成行；只有「我」那一行有「写下/编辑」按钮，他人行无任何编辑入口。
- **AC-17（S）** `thought.save` 的 `memberId ≠ 操作者` → 422「感想独立归属」。OWNER 也不能代写（服务端无豁免）。

## 图层区分

- **AC-18（P）** 家庭记录 = 实心照片气泡（正圆、白色 2.5px 实线描边、琥珀光晕）；
  推荐未打卡 = 灰度虚线倒立水滴；推荐已打卡 = 绿色实心倒立水滴 + 白勾。
  水滴与正圆形状互不混淆，打卡状态用填充/描边/对勾区分，图例三行与之对应。
- **AC-19（P）** 已打卡推荐徽章点击 → 详情 Sheet 显示关联的旅行记录并可跳转；取消打卡后徽章回到虚线态。

## 推荐清单

- **AC-20（P）** 必打卡页显示进度环 + 百分比 + `已打卡 n / 总数 m`；按类别分组；
  「未打卡」筛选为空时显示「清单已全部点亮」空状态。
- **AC-21（C/P）** 推荐清单数据带 `source` 字段「人工整理·公共常识清单」，页面明示来源；
  代码中不出现「国家地理」「Lonely Planet」等第三方背书文案。

## 必打卡点编辑（增删改 · 自定义分组 · 权限）

> 设计（已与用户确认）：原 5 类（世界遗产 / 风景名胜区 / 自然奇观 / 古城古镇 / 城市地标）保留为「主题标签」，
> 每个点可单独选其一；另设一层「自定义分组」——每个点可归入一个自定义分组。预置点与自定义点一视同仁，均可编辑/删除。
> 权限：成员（MEMBER，含创建者）及以上可编辑/分组/增删；仅查看者（VIEWER）只读。

- **AC-47（P）** 必打卡页默认按「自定义分组」视图：含「未分组」区块（预置点全部归未分组）；
  OWNER/MEMBER 可见「＋ 新建分组」「＋ 添加必打卡点」管理条；VIEWER 仅见只读态
  （无管理条、列表行内无编辑/删除按钮、详情无编辑/删除入口），页面副行明示「仅查看」。
- **AC-48（P）** 新建自定义分组：点「＋ 新建分组」→ 填写名称 → 创建后列表出现该分组区块（标题含计数）；
  可重命名 / 删除分组（删除时二次确认并说明组内点移回「未分组」）。
- **AC-49（P）** 新增必打卡点：点「＋ 添加必打卡点」→ 填写名称、选择城市/区县（下拉按省分组，
  选中后自动带出单位名 / 省 / 经纬度坐标，可手动微调）→ 选择主题（5 类之一）与所属分组 →
  保存后列表立即出现该点、进度总数 +1、地图推荐图层随之出现该点、搜索可达。
- **AC-50（P）** 编辑必打卡点：点列表行 → 详情 Sheet → 「编辑」→ 修改名称 / 主题 / 分组 / 理由 / 坐标 →
  保存后列表与详情实时更新；预置点与自定义点一视同仁均可编辑。
- **AC-51（P）** 删除必打卡点：点行 → 详情 → 「删除」→ 二次确认（说明打卡记录一并清除）→
  确认后该点从列表移除、总数 -1、其打卡记录同步清除；列表进度卡随增删实时刷新。
- **AC-52（P）** 分组归属调整：详情或表单内的「所属分组」下拉可将某点移入 / 移出分组；
  移出后回到「未分组」；删除分组后组内点全部回退「未分组」（不删除点本身）。
- **AC-53（P）** 权限门控：以 VIEWER（爷爷 · 陈守成）进入必打卡页，无「添加必打卡点 / 新建分组」入口、
  列表行内无编辑/删除按钮、详情无编辑/删除入口；切回 OWNER/MEMBER 后入口恢复。
- **AC-54（C/S）** 服务端 RBAC：`{type:'spot.add'|'spot.update'|'spot.delete'|'spotGroup.*'}` op 经
  `/api/...` 推送时，角色 < MEMBER 返回 **403**（服务端 `POLICY['spot.manage']=ROLE.MEMBER`）；
  MEMBER/OWNER 可写入（op 仅追加到 `DB.log`，客户端按 op-log 重建，服务端不另存 spot 状态）。
- **AC-55（P）** 端到端验收脚本 `tools/test-spots.js` 13 项断言全过
  （预置点可见 / 新建分组 / 增点 +1 / 编辑 / 删除 -1 / 搜索可达 / VIEWER 只读 / 0 console 错误）。
- **AC-56（P）** 误删预置点可恢复：当存在被删/缺失的预置点时，管理条出现「↺ 恢复预置(N)」入口（N=缺失数）；
  点按 → 二次确认 → 仅补回当前不存在的 `SPOTS` 条目（按 `id` 比对），**不影响**用户已有的自定义点 / 分组 / 编辑结果；
  全数补回后入口自动消失。恢复时同步推送 `spot.add` op（若连 NAS）。
- **AC-57（P）** 经详情 Sheet「删除」预置点后，管理条**立即**重建并正确反映「恢复预置」入口（无需离开页面再返回）；
  端到端脚本 `tools/test-spots.js` 现 18 项断言全过（含模拟误删→恢复闭环）。

## 毛玻璃克制 · 移动端 Sheet · Apple 风格

- **AC-22（C）** `backdrop-filter` 仅出现在 `.glass/.sheet/.tabbar/.photo-viewer` 相关规则；
  卡片（`.card`、`.list`）背景为不透明 `--bg-elevated`。全站无霓虹渐变、无拟物纹理。
- **AC-23（P）** 桌面（>860px）悬停城市弹出毛玻璃卡，内容仅：地点、日期、成员头像、照片数、1 张代表图、「查看旅行」；
  移动端（≤860px 或 coarse pointer）悬停卡不出现，点击改弹底部毛玻璃 Sheet（可下滑关闭/点 scrim 关闭/Esc 关闭）。
- **AC-24（P）** 深色模式下切换主题，地图底图/填充/标记/文本全部切换为暗色且对比度不降级（无硬编码浅色残留）；
  「减少动效」开关打开后 spring 动画时长变为 1ms（**C**：`data-motion="reduce"` 规则存在）。
- **AC-25（P）** TabBar 项数 = 5（地图/时间线/必打卡/家庭/我的）；桌面 Rail 同项数 + 设置入口。

## 本地优先与 NAS

- **AC-26（P/S）** 不配置服务端时 App 全功能可用（数据在 IndexedDB）；
  配置后「测试连接」返回 `{"ok":true,"version":…}`，推送/拉取正常，
  且**断网/关闭服务端后 App 仍可完整使用**（本地优先）。

## 成员资料编辑（家庭页）

- **AC-27（P）** 家庭页点按成员行打开编辑 Sheet：姓名、家庭关系可修改并即时保存（头像首字随姓名联动）；
  保存后地图筛选条、悬停卡头像、感想署名等所有成员展示处同步更新。
- **AC-28（P）** 权限控制：本人只能改自己的姓名/关系（角色区不出现）；仅创建者可见角色分段选择并可变更；
  以 VIEWER 身份打开自己的 Sheet，角色区与「移出家庭」均不可见。
- **AC-29（S）** 伪造 MEMBER 身份推送 `member.update` 修改**他人**资料 → **403**；
  `member.role` 由 MEMBER 推送 → **403**；唯一创建者降级（无其他创建者）→ **422**「必须保留至少一位创建者」；
  `member.update` 的 patch 中夹带 `role` 字段 → **422**（角色必须走 member.role）。

## 推荐图层标记形状

- **AC-30（P）** 地图推荐图层中，未打卡与已打卡点位均为倒立水滴（圆头 + 朝下尖端），形状一致；
  已打卡 = 绿色实心 + 白勾，未打卡 = 灰度虚线，与家庭正圆照片气泡一眼可辨；图例两行与画布一致。
- **AC-31（P）** 水滴尖端与圆头均可点击命中（命中区域覆盖整个水滴，非仅圆心），悬停/点击行为与改造前一致。

- **AC-33（P）** 移动端点击地图气泡 → 底部 Sheet → 进入旅行详情 → 点「‹ 返回地图」同样回到地图；
  直接深链打开详情页（无来源 Tab）时返回目标为地图。

## 成员增删（家庭页）

- **AC-34（P）** 创建者在家庭页点「＋ 添加成员」→ Sheet 填写姓名（必填，1–12 字）/ 家庭关系（≤10 字）/ 角色
  （创建者/成员/仅查看，默认「成员」，附权限说明）→ 添加后成员立即出现在成员列表、地图成员筛选与感想署名中；
  姓名为空或超长时给出错误提示且不写入。
- **AC-35（P）** 「用邀请码加入家庭」：输入正确邀请码 + 姓名 → 以「成员」身份加入并切换为该身份；
  邀请码错误 / 过期时提示「邀请码无效或已过期」且不产生成员。加入入口对任何身份可见（家庭空间默认私密，无公开注册）。
- **AC-36（P）** 移出成员：二次确认弹窗列出该成员的内容数量（旅行/照片/感想/精选）；确认后成员从列表消失，
  但其创建的旅行、照片、感想、精选**全部保留**，署名统一降级为「已退出成员」（时间线/详情/旅行册导出均如此）；
  移出后该成员编辑入口不可见，「进入」按钮不再出现。
- **AC-37（P/S）** 权限：非创建者看不到「＋ 添加成员」与「移出家庭」；不能移出创建者；不能移出自己
  （VIEWER/MEMBER 调 removeMember 直接抛错）。服务端：MEMBER 推 `member.add` → **403**；
  OWNER 推 `member.remove` 移出创建者 → **422**；移出不存在的成员 → **404**；
  重复 id 的 `member.add` → **409**；正常 OWNER 添加/移出 → **200**。

## 官方底图（天地图 · 审图号）

- **AC-38（P）** 未配置 Token 时进入地图：显示简化示意底图，且地图上出现
  「当前为示意底图（非正式）· 请在设置 → 地图底图配置天地图 Token 启用官方底图」提示；
  审图号条隐藏。配置 Token 后（设置页填入并「保存并启用」→ 回到地图）：提示消失，
  审图号条出现，底图切换为天地图瓦片（vec_w + cva_w），打卡高亮与水滴图层不变。
- **AC-39（P）** 官方模式下地图页左下角显著标注「审图号：GS(2024)2767号 · © 天地图 自然资源部」，
  不与筛选条/缩放控件重叠（桌面与移动端均避让，脚本断言 bbox 不相交）；
  审图号文本可在设置页配置。
- **AC-40（S/P）** 瓦片对齐：`tools/test-tile-math.mjs` 验证 proj() 与 tileView() 同一
  Web Mercator 线性空间——任意 z（3~18）下「屏幕坐标 → 归一化瓦片坐标 → 瓦片矩形 → 屏幕坐标」
  往返误差 < 1e-6 px；瓦片层级选取 z = round(log2(2π·scale/256))，目标层级瓦片实际绘制宽高 ≈ 256px。
- **AC-41（P）** 瓦片请求格式：`https://t{s}.tianditu.gov.cn/DataServer?T=vec_w|cva_w&x&y&l&tk`，
  s = (x+y+z) mod 8，l ∈ [2,18]，tk 与设置一致（Playwright 网络断言）。
- **AC-45（P）** 降级兜底（官方瓦片失败不白屏）：官方模式下简化省份底图**始终先绘制**，
  官方瓦片（不透明）加载成功后覆盖其上；瓦片失败/离线/请求挂起（9s 超时按失败计）时
  省份边界自然透出，地图**永远可见不空白**；同时左下角提示「官方底图加载失败，已回退示意底图
  （请检查天地图 Token 或网络）」并**隐藏审图号条**（避免虚假合规标注）；
  验收脚本 `tools/test-degraded.js` 一键复现（4 项断言全过）。
- **AC-42（S）** `GET /config.json` 返回 `{ tiandituToken: <TIANDITU_TOKEN 环境变量> }`；
  App 启动时拉取并在本地未设置 Token 时注入为默认值（curl 可复现，无 Token 时返回空串）。
- **AC-43（P）** 设置 → 地图底图分区：Token 输入 + 「保存并启用」+ 底图来源状态行
  （官方底图显示「天地图（官方 · 带审图号）+ 审图号」，未配置显示「示意底图（非正式）」）；
  「如何获取 Token」Sheet 给出申请/粘贴/合规标注/NAS 统一配置四步说明；
  「关于与合规 → 地图底图合规」说明天地图来源、审图号与边界口径。
- **AC-44（C）** 全程（降级 + 官方 + 设置切换 + 移动端）console 错误数为 0；
  验收脚本 `tools/test-basemap.js` 一键复现（19 项断言全过）。
- **AC-46（P）** Token 诊断（区分「Token 无效」与「域名白名单未放行」）：
  服务端 `GET /api/tile-test?tk=xxx` 由 Node 直接请求天地图样例瓦片（无 CORS/Referer 限制），
  返回 `{ httpStatus, contentType, isImage, verdict }`——`valid`（200+图片）/`invalid_or_blocked`
  （418 WAF）/`network_error`；设置页「测试连接」按钮展示结论与排查指引（复制完整/浏览器端类型/
  未过期/域名白名单需含 localhost·127.0.0.1·局域网 IP）；「如何获取 Token」Sheet 含「配置允许域名」
  关键步骤；地图页失败提示引导到该诊断。验收脚本 `tools/test-tile-test.js`（4 项断言全过）。
