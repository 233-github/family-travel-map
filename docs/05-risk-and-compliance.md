## 🟠 R2 · 推荐清单版权

- 当前 MVP 清单为**人工整理的公共常识型内容**（景点名称 + 一句话理由），
  未复刻任何榜单排序、评分、榜单名（如「XX 50 景」「国家地理评选」）。
- **禁止**：抓取/搬运马蜂窝、小红书、携程、国家地理等平台的榜单数据与配图；
  景点文案与**官方页面/百科**重复率过高同样有侵权风险，理由文案需人工撰写。
- **禁止**：在无授权的情况下标注「国家地理推荐」「XX 联合出品」等背书。
- 扩充流程（生产）：编辑审核 → 来源登记（`source` 字段）→ 法务抽检；
  涉及付费榜单/机构数据一律走采购授权。
- 景点营业信息（票价、开放时间）易过期，MVP 刻意未收录；若未来收录需注明「以官方为准」。

## 🟠 R3 · 照片隐私与 EXIF

**已实现的缓解**：
- 上传时通过 Canvas 重绘压缩（480px 缩略 / 1600px 原图），**重绘即剥离 EXIF**（含 GPS、机型、时间），元数据强制 `exifStripped: true`；
- 家庭空间默认 `family` 可见，无公开分享链接；导出文件明示「仅家庭可见」。

**残余风险与建议**：
1. **人脸与儿童**：家庭照片常含未成年人面部。建议生产版增加「上传前提示」、
   相册分享时的水印选项；如引入云端识别必须明示并获单独同意（《个人信息保护法》对未成年人信息的单独同意要求，14 岁以下需监护人同意）。
2. **原文件**：当前 `full` 为 1600px JPEG dataURL，原始文件不落盘（读取时即销毁）；
   若未来保留原件，EXIF 剥离必须改为二进制级处理（如 piexifjs/exiftool 服务端批处理）。
3. **NAS 暴露面**：家庭 NAS 常被用户开放到公网。生产部署建议：
   - 默认仅监听内网，公网走 VPN/Tailscale 或 HTTPS 反代 + 认证；
   - `server/server.js` 演示版**没有鉴权**（`X-Member-Id` 可伪造），生产必须加真实会话（登录/JWT/设备密钥），
     并给 `/sync/*` 加速率限制与 HTTPS（否则邀请码与照片明文传输）。
4. **备份即复制**：`server/data/family.json` + 照片对象存储是全部家底，
   建议在 NAS 上配置每日快照/异地备份，并在设置页提供「导出全量 JSON」。
5. **成员退出后数据归属**：被移出成员的感想与照片归属记录保留（避免破坏家庭叙事完整性），
   生产建议提供「退出时带走我的内容/授权家庭保留」二选一。

## 🟡 R4 · 其他工程风险

| 风险 | 说明 | 缓解 |
|------|------|------|
| 双端规则漂移 | 前后端各写一份 RBAC/上限逻辑，容易改一漏一 | 生产合并为共享 npm 包；当前 `rules.js` 与 `server.js` 注释互相引用 |
| op-log 合并 | 多端并发编辑同一感想时最后写入生效 | MVP 家庭场景可接受；升级为 per-entity 版本号/CRDT |
| localStorage 隐身模式 | 隐私模式可能限制存储 | 已 try/catch 降级为内存态（刷新丢失），不静默崩溃 |
| 照片体积 | dataURL 存 IndexedDB，百张级 OK，万张级需换 Blob+对象存储 | 生产：文件分仓 + 裁剪任务队列 |
| 合规口径变化 | 行政区划调整（如县改区）导致分母变化 | `geo-units.json` 由 `tools/build_units.py` 可再生；分母 333 显式存于数据文件 `total` 字段，不硬编码 |
